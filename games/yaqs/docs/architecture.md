# Устройство YAQS

## Рабочий путь

```text
TXT / JSONL → Document / Page → фрагменты 512/128 → Qwen → SQLite
                                                         ↓
                          CLI / MCP → KnowledgeService → контекст со ссылками
```

- `documents.py` проверяет готовый текст и сохраняет происхождение страниц.
- `chunking.py` создаёт окна токенов в пределах страницы с точными смещениями.
- `embedding.py` содержит закреплённый профиль модели, кеш и ленивую загрузку.
- `ingest.py` отвечает за возобновляемый импорт и транзакционные пакеты векторов.
- `locking.py` сериализует писателей, включая удаление книги.
- `store.py` владеет SQL, индексами, ссылками и согласованным чтением.
- `context.py` объединяет только точные пересечения исходного текста.
- `maintenance.py` делает согласованные резервные копии и полную пересборку.
- `diagnostics.py` проверяет готовность без скачивания и инференса.
- `service.py` — общий слой чтения для `cli.py` и `mcp.py`.

## Данные и инварианты

Схема 2: `books`, `pages`, `chunks`, `chunk_vectors`, `chunks_fts`, `config`.
`books.id` и `chunks.id` используют `AUTOINCREMENT`: удалённый идентификатор
не выдаётся новому источнику или тексту в той же базе. Перестройка одной книги
сохраняет её идентичность, но создаёт новые идентификаторы фрагментов.

Внешние ключи каскадно удаляют страницы и фрагменты. Триггеры синхронизируют FTS5
и удаляют старые векторы. Векторы имеют 1024 измерения и единичную L2-норму.
Текст страницы и диапазоны фрагментов — основание для цитирования; исходный PDF
не нужен при чтении. Профиль модели проверяется при открытии базы.

Qwen3-Embedding-0.6B закреплён на revision
`97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`, без квантования. Вход документа:
`{title}\n{chapter}\n\n{text}`. Запрос получает поисковую instruction. CPU использует
FP32, CUDA — BF16, сохранённый нормализованный вектор — float32. Изменение профиля
модели требует полной пересборки, а не смешивания векторов разных профилей.

Полная пересборка читает схемы 1 и 2 только как источник текста. Обычная работа
использует схему 2. Новая база публикуется после проверки целостности; исходная
остаётся доступной для отката. Резервная копия использует SQLite backup API,
чтобы учитывать WAL, и не копирует открытый файл побайтово.

## Границы

YAQS не распознаёт PDF, не управляет библиотекой купленных файлов и внешней очередью
импорта, не переводит запросы и не генерирует ответы LLM. Эти задачи не должны
попадать в слой хранения или MCP. Внешний сборщик отвечает за то, какие источники
разрешено импортировать повторно.

Одноразовые OCR-обработчики, эксперименты с языками и отчёты остаются в
`workspace/vectordb`. Продуктовые команды не зависят от этой директории.
Для GPU переиспользуется Nix-окружение репозитория; отдельный сервер Studio
для поиска или хранения не нужен.

## Ограничения

- Многоязычность модели не гарантирует одинакового ранжирования переводов вопроса.
- FTS5 ищет токены без перевода; гибридный режим требует отдельной оценки качества.
- Нет разметки глав и фильтра удаления колонтитулов: исходный текст сохраняется.
- Одинаковый текст на разных страницах остаётся отдельными источниками; сборка
  контекста убирает пересечения диапазонов, но не повторы содержимого всей книги.
- Идентичность импорта определяется байтами входного файла; семантическое
  обнаружение дубликатов книг не выполняется.
- После полной пересборки новый файл имеет собственную нумерацию ссылок.
