# Формат текста и результатов

## JSONL

Одна строка на страницу. `page` — положительный исходный номер, `text` — строка.

```json
{"title":"Game book","author":"Author","page":20,"total_pages":300,"text":"Page text","extraction":"pdf-text","source":"/books/book.pdf"}
```

Название и автор берутся из первой записи, либо из `--title` и `--author`.
`chapter`, `page_label`, `source`, `source_sha256` и данные происхождения
необязательны. Номера страниц уникальны. Если указан `total_pages`, импорт требует
все страницы от 1 до этого числа. Пустые страницы сохраняются, без эмбеддингов.

`extraction` различает `pdf-text` и `ocr-text`; без поля используется `ocr-text`.
Для распознанной страницы можно передать:

```json
{"title":"Game book","page":20,"text":"Recognized text","ocr":{"job_id":"job-id","model":{"revision":"revision"},"meta":{"truncated":false}}}
```

Страница с `ocr.meta.truncated: true` отклоняется. Происхождение сохраняется
в базе вместе с текстом. Формат не привязан к одному OCR-серверу.

## TXT

UTF-8 текст без разметки страниц получает номер 0: ссылки указывают диапазон
символов, а не выдуманную страницу. Символ form feed (`\f`) разделяет явно
пагинированный TXT. BOM и окончания строк нормализуются, абзацы, таблицы Markdown
и отступы кода сохраняются. Для точных ссылок на PDF удобнее JSONL.

Хеш книги считается по байтам входного TXT/JSONL, а не исходного PDF. Изменение
форматирования входного файла меняет его идентичность; канонический вход следует
хранить неизменным между повторными импортами.

## Контекст

`search` и `passage` возвращают `{hits, context}`. В блоке:

- `text`, `start_char`, `end_char`, `token_count`, `sha256`, `citation` описывают
  весь собранный диапазон исходного текста;
- `id`, `anchor_chunk_id`, `ordinal` и оценки относятся к лучшему исходному
  фрагменту блока;
- `chunk_ids` и `source_chunks` перечисляют участвовавшие фрагменты и смещения;
- `book_id`, `title`, `author`, `page_number`, `source_path`, `provenance` позволяют
  проверить источник. Номер страницы PDF — физический, начиная с 1.

Один снимок SQLite используется для ранжирования и чтения исходных диапазонов.
Разные страницы и книги не объединяются; промежутки между диапазонами не
заполняются. Слишком большой кандидат пропускается целиком, текст не обрезается.
После объединения применяются лимит блоков и бюджет текста.

`context` сообщает число кандидатов, выбранных фрагментов, готовых блоков,
использованных токенов и пропущенных результатов. Допустимый `max_tokens` —
256–16384. Для явно запрошенных соседей `passage --neighbors N` предел одного
блока равен общему бюджету, с приоритетом центрального фрагмента.

Векторный `score` — cosine similarity; лексический — обратный ранг FTS5;
гибридный — RRF. Ни одна из этих оценок не является вероятностью правильного
ответа. Ближайший фрагмент может существовать и для вопроса вне тематики базы.
