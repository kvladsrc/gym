# Ревью: M8 — разделы по результату, модель внутри; удаление ассетов; CI

Критик, 2 итерации, ACCEPT (ADR-004).

## Итерация 1 — REVISE

1. Можно было удалить результат задания, от которого зависит ждущее
   задание (проверялись только прямые входы): нижнее задание падало с
   «файл не найден», а при общем файле молча брало удалённый ассет. Плюс
   гонка между проверкой входов и записью задания.
2. `python311` в билд-ноде перехватывал `python3` у `python314` (в
   `symlinkJoin` выигрывает первый) — все задания CI получили бы 3.11.
   Теперь в образе только команда `python3.11`.
3. Давняя ошибка диспетчера: ссылка на поток рабочего сбрасывалась при
   каждом опросе, и `stop()` не дожидался потоков — студия закрывала базу,
   пока рабочий мог писать в неё.

Рекомендации приняты: понятная ошибка для конфига с `[[tabs]]`; битая
запись о сервере не мешает запуску; MCP не отдаёт пути удалённых файлов;
прошлые задания не выпадают из истории при смене модели на порту; выбор
модели запоминается только по щелчку и переживает смену задачи.

## Итерация 2 — ACCEPT

Доделано после: настроенные параметры замораживают автоматический выбор
модели (иначе готовность другой модели сбрасывала бы их); число вариантов
и входы всегда подгоняются под выбранную модель; задание, зависящее от
уже удалённого результата, отклоняется сразу (422), а не в очереди.

Оставлено: PATCH удалённого ассета, 409 вместо 422 при повторе с удалённым
входом, отказ ждущих заданий серверов, которых нет в конфиге.
