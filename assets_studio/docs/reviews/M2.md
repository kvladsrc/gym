## Итерация 1

Вердикт: **REVISE**, 1 блокирующее замечание и 9 рекомендаций.

### Итерация 1: блокирующее

1. **Ctrl+C не останавливал студию при открытом потоке событий или
   долгом ожидании задания.** Веб-интерфейс держит поток постоянно, так
   что остановить студию было бы нельзя.
   *Исправлено:* `timeout_graceful_shutdown` у uvicorn; закрытие студии
   будит все ожидания (`Studio.closing`), поток событий завершается.
   Тест: SIGINT при открытых потоке и ожидании — выход быстрее 10 с.

### Итерация 1: рекомендации

| № | Суть | Решение |
| --- | --- | --- |
| 1 | Нет проверки Host у REST: DNS rebinding открывал API веб-странице | `TrustedHostMiddleware`: только localhost и адрес привязки. Тест |
| 2 | Подписка SSE создавалась вне генератора — утечка при быстром уходе клиента; очередь без границ | Подписка внутри генератора; вместо очереди — множество id, события одного задания склеиваются |
| 3 | Блокирующие вызовы в event loop внутри SSE | Чтение вкладок и заданий в пуле потоков |
| 4 | Ожидание занимает рабочий поток до 600 с | Не меняли: при одном пользователе и нескольких агентах лимит недостижим; закрытие студии будит ожидания |
| 5 | MCP: формат `"id:index"` отличался от REST, ошибки разбора; `wait_for_job` без путей; таймаут 300 с | `input_jobs` — объект `{job_id, output_index}` как в REST; `output_paths` в ответе; таймаут 60 с с подсказкой «вызвать снова» |
| 6 | `import_asset` читал файл целиком до проверки размера | Сначала `stat()` и лимит |
| 7 | Пропавший файл → 500; имя файла при скачивании — хеш | 410; `Content-Disposition` с понятным именем. Тест |
| 8 | Два формата ошибок (`detail` строкой и списком) | Всегда строка. Тест |
| 9 | `POST /mcp` без слэша давал редирект | MCP обслуживает ровно `/mcp` |

## Итерация 2

Вердикт: **ACCEPT**. Критик проверил исправления на запущенной студии:
SIGINT при открытом потоке событий и при 600-секундном ожидании завершает
процесс за ~3,3 с; чужой Host отклоняется и на `/api`, и на `/mcp`.

Учтены рекомендации: неизвестные пути `/api/...` отвечают в формате
ошибок API (а не текстом корневого монтирования MCP); в коде отмечено,
что остановку ограничивает таймаут uvicorn, а статический UI в M3 нужно
монтировать до MCP. Асинхронное ожидание отложено, критик согласился.
