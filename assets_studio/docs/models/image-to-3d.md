## TripoSR — сервер удалён (октябрь 2026)

TripoSR и Stable Fast 3D удалены: цепочку Hunyuan3D-2mini → Paint ничто не
догнало (итог ниже). Замеры — для истории.

Проверено 29 сентября 2026 на RTX 3070 Laptop (8 ГБ).

| | |
| --- | --- |
| Лицензия | MIT (код и веса) |
| Ревизии | исходники `107cefdc`, веса `5b521936` |
| Загрузка модели | 53 с (веса из локального кеша) |
| Генерация | 6,4 с на картинку 1024×1024, `mc_resolution=256` |
| Видеопамять после генерации | ~3,2 ГБ (по `nvidia-smi`, справочно) |
| Результат для героя платформера | 32 298 вершин, 64 596 треугольников, замкнутая сетка, GLB 1,3 МБ — совпадает с прежним прогоном прототипа |
| Проверка контракта | 0 ошибок, 1 предупреждение |

Предупреждение — «результат не зависит от seed»: TripoSR — модель прямого
прохода, одинаковая картинка всегда даёт одинаковую сетку. Поэтому
`max_count = 1`, а варианты в 3D получаются через варианты входной
картинки. Проверка запускается с `--allow-seed-independent`.

Качество: силуэт и поза сохраняются, лицо, пальцы и фактура упрощены
(проверено ещё в прототипе платформера, ныне удалённом). Это быстрый
черновик формы.

## Итог сравнения (октябрь 2026)

Stable Fast 3D и Hunyuan3D-2mini (лицензия не действует в ЕС) добавлены и
сравнены с TripoSR на ~240 вариантах с оценками. Выбрана цепочка
**Qwen-Image → Hunyuan3D-2mini → Hunyuan3D-Paint**: ровные фигуры,
правдоподобные скрытые стороны, текстура по исходной картинке. Числа,
промпты и ограничения — в [руководстве](../guides/3d.md). TRELLIS не
проверен (вероятно, не помещается в 8 ГБ).

## TripoSG — на пробе (октябрь 2026)

После поста на Reddit в комментариях написали, что «Tripo 2» работает на
8 ГБ. Открытого Tripo 2 нет: Tripo 2.0–3.x и P1.0/H3.1 доступны только
через API. Открытые модели VAST — TripoSR (удалён), TripoSG (форма,
март 2025, MIT, по README «≥ 8 ГБ») и TripoSplat (2026, только гауссианы,
без сетки). Вероятнее всего, речь шла о TripoSG; добавлен сервер
`triposg` (порт 9115).

Проверено 16 октября 2026 на RTX 3070 Laptop (8 ГБ).

| | |
| --- | --- |
| Лицензия | MIT (код и веса) |
| Ревизии | исходники `fc5c4099`, веса `2c1c516d` |
| Загрузка модели | 7,5 с (веса fp32 ~7,5 ГБ из кеша, на GPU — fp16) |
| Генерация | ~60 с на форму: 50 шагов, сетка 512³ |
| Видеопамять | пик ~6,2 ГБ (по `nvidia-smi`), GPU до 63 °C |
| Сетка | 0,8–1,2 млн треугольников, 5 из 6 не замкнуты |
| Проверка контракта | 11 проверок, 0 ошибок, 0 предупреждений |

Поверхность строит diso (dual marching cubes на CUDA), его буферы
выделяются мимо аллокатора PyTorch. С трансформером на GPU орку и рыцарю
памяти не хватило; diso не проверяет ошибку выделения, пишет в чужую
память, и CUDA-контекст процесса ломается: все следующие задания падают с
`illegal memory access`. Поэтому на время извлечения поверхности
трансформер и DINOv2 уходят в ОЗУ.

Сравнение с Hunyuan3D-2mini на трёх персонажах из «Finish the game»
(отшельник, орк, рыцарь-призрак; та же картинка, затем тот же Paint с
`max_faces=40000`):

- TripoSG чётче в мелочах (мышцы, складки, заплаты), но поверхность
  шумнее, а тонкое разваливается: ткань рыцаря распалась на полосы, мех
  на сапогах орка — на нити, лицо и борода отшельника — бугристая каша.
- Hunyuan3D точнее держит силуэт (орк у TripoSG уже, чем на картинке) и
  цельнее в целом.
- Paint работает с формами TripoSG без доработок: оси и кадр совпадают
  (Y вверх, перед к +Z, масштаб на ~5 % меньше).

### Сравнение на случайной выборке (`sweep:triposg1`)

30 картинок из библиотеки, отобранных случайно по категориям с любой
оценкой: растения, дома, животные, персонажи, предметы, камни и арки по 5
(камней 3), 2 диорамы. Обе модели с параметрами по умолчанию, затем Paint
(`max_faces` 60k). Страница сравнения: `just sweep gallery`, четыре вида на
модель (спереди, ¾, сзади, сверху).

| | Hunyuan3D-2mini | TripoSG |
| --- | --- | --- |
| Время формы, медиана | 82 с | 65 с |
| Треугольников, медиана (макс.) | 0,87 млн (2,0 млн) | 1,31 млн (4,6 млн) |
| Замкнутых сеток | 30 из 30 | 13 из 30 |
| Paint, медиана | 82 с | 95 с (дольше упрощать) |

- **TripoSG лучше**: тонкое и ветвистое (сухие деревья — больше тонких
  веток, ярусы ели раздельнее), чёткость граней в архитектуре (наличники,
  фахверк), верность картинке там, где Hunyuan додумал (второй фронтон у
  разрушенной часовни), лист персонажа «спереди + сзади» без летающих
  обломков.
- **Hunyuan лучше**: диорамы — ставит их ровно, с плоским основанием и
  деталями внутри, а TripoSG запекает в модель наклон изометрической
  камеры и рвёт пол; органические камни (у TripoSG менгир вышел плоской
  гранёной плитой); густая листва (у TripoSG куст шумнее и после Paint
  темнее); замкнутые сетки.
- **Поровну**: животные, предметы, арки, ступени, персонажи — разница в
  мелочах в обе стороны.
- TripoSG иногда поворачивает объект к своей «передней» стороне (курица
  анфас вместо профиля с картинки); Paint это не мешает.

Итог: TripoSG — рабочая альтернатива, а не замена: по умолчанию
Hunyuan3D-2mini, TripoSG — для ветвистого и резкой архитектуры.

## Hunyuan3D-2.1 + Paint 2.1 — на пробе (октябрь 2026)

Серверы `hunyuan3d21` (форма) и `paint21` (PBR-покраска) на 8 ГБ:
официально 2.1 требует ~10 ГБ для формы и ~21 ГБ для покраски. Форма
выгружает модели по фазам (пик 7,1 ГБ); в покраске на GPU только UNet и
VAE, текстовый энкодер — через хук accelerate, DINOv2 — на один вызов,
feed-forward UNet по кускам в 64 токена (пик 6,1 ГБ при 6 видах по 512).
Сравнение на той же выборке `triposg1`: 2.1 + Paint 2.1 против 2mini +
Paint 2.0 (Paint 2.1 на формах 2mini не проверялся).

| | 2mini + Paint 2.0 | 2.1 + Paint 2.1 |
| --- | --- | --- |
| Время формы, медиана | 82 с | 197 с |
| Время покраски, медиана | 82 с | 107 с |
| Замкнутых сеток | 30 из 30 | 30 из 30 |
| Материал | цвет (тени запечены) | PBR: цвет + metallic/roughness |

- **Форма 2.1 лучше**: верность картинке в руинах (нет выдуманного
  второго фронтона, как у 2mini), перья орла, резче камень и кора.
- **Форма 2.1 хуже**: листва — крона лиственного дерева стала гладкими
  «воздушными шарами», ярусы ели — плоскими дисками, курица глаже;
  животных иногда разворачивает от вида на картинке (лошадь анфас).
- **Остальное поровну**: персонажи, предметы, ступени, диорамы (обе
  ставят ровно).
- **Paint 2.1 лучше**: цвет без запечённых теней (светлее и ровнее —
  то, что нужно движку со своим светом), отдельные metallic/roughness,
  вернее цвета на арке с рунами и на руинах.
- **Paint 2.1 хуже местами**: волк темнее картинки, у гоблина ноги
  розовее; на 2.0 тени «рисуют» объём там, где освещения нет.

Итог: форма по умолчанию остаётся 2mini (2.1 в 2,4 раза дольше и хуже
на листве); 2.1 — для руин и архитектуры, где 2mini додумывает. Paint
2.1 — кандидат в покраску по умолчанию для игровых ассетов (PBR, свет не
запечён); стоит проверить его на формах 2mini и TripoSG.
