# Риггинг и анимации: рабочие цепочки студии

## Что делает каждая модель

| Сервер | Вход → результат | Совместимость и подготовка |
| --- | --- | --- |
| `mia` | GLB персонажа → FBX с костями Mixamo и весами | Гуманоиды; поза покоя, пальцы, экспорт текстур, сварка и гладкие нормали настраиваются/выполняются внутри сервера |
| `skintokens` | GLB → FBX со скелетом по форме | Произвольная форма; кости `bone_N`, а не фиксированный скелет Mixamo |
| `unirig` | GLB → FBX со скелетом по форме | То же; другая модель предсказания скелета и весов |
| `kimodo` | Текст → скелетная анимация FBX | SOMA, 77 суставов; совместимые суставы получают имена Mixamo, дополнительные — `soma_*`; сетки персонажа в результате нет |
| `mocapanything` | Видео + риг → персонаж с анимацией FBX | Работает на скелете входного рига; для `bone_N` автоматически читается анатомия четвероногого, для именованных костей сохраняются имена |
| `gvhmr` | Видео человека + риг Mixamo → персонаж с анимацией FBX | Предсказывает SMPL-X, переносит 22 кости тела на риг; пальцы и контакт с оружием не предсказывает |
| `animation_tools` | Риг; либо риг + движение → FBX | Blender без нейросети: проверка/подготовка рига и перенос гуманоидной анимации с учётом поз покоя и вращений |

Имена костей — только часть совместимости. Позиции суставов, направления
костей, масштабы, позы покоя и наличие скина тоже существенны. Поэтому
скелет Kimodo нельзя считать готовой анимацией конкретной сетки MIA только
по общему префиксу `mixamorig:`.

## Какие исправления теперь внутри заданий

- Экспорт текстур и сварка сетки уже были в серверах риггинга.
- Приведение собственного рига к соглашениям MoCapAnything, опорная
  rest-анимация, именование четвероногих и удаление блокировок вращений
  уже были в MoCapAnything; вызывать его подготовительные скрипты вручную
  не нужно.
- `retarget-motion` заменяет ручной вызов `asset_processing/retarget.py` для Kimodo/Mixamo.
  Он сам сбрасывает старую анимацию цели, проверяет кости и скин,
  нормализует веса, сохраняет текстуры и экспортирует анимированный FBX.
- Общий перенос, в том числе внутри GVHMR и MoCapAnything, проверяет и
  нормализует веса. Вершины без весов не угадываются: такой вход отклоняется.
- Перенос полных вращений сохраняет скручивание и движения конечных
  суставов, которые терялись при переносе только направлений костей.
- Старые клипы Kimodo распознаются с приоритетом настоящих Mixamo-костей
  перед одноимёнными дополнительными суставами SOMA. Новые экспорты
  устраняют такие коллизии именованием `soma_*`.
- Изменения частоты кадров и округление диапазона при импорте FBX
  учитываются в общем переносе. Экспорт не упрощает ключи.

В проверенном старом риге стражника были все 22 кости и не было вершин без
весов. Максимальное отклонение суммы весов от единицы составляло около
1,7 %. Для готового FBX из нового графа оно меньше 1e-6; все координаты и
вращения конечны на всех 120 кадрах.

## Как собирать

1. **Человек из текста:** сетка → MIA; текст → Kimodo; два результата →
   `animation_tools / retarget-motion`. Результат — персонаж с клипом для
   импорта в движок как Generic, без дополнительного Humanoid-ретаргетинга.
2. **Человек из видео:** сетка → MIA → вход `rig` GVHMR; видео → вход `video`.
   Отдельный сервер подготовки между ними не обязателен.
   Перед обоими серверами можно поставить `birefnet / video-to-video`;
   в MoCapAnything тогда включите `background_removed`, чтобы не вырезать
   фон повторно. В GVHMR с `camera=moving` подайте исходный фрагмент с фоном
   в отдельный вход `camera_video`: ориентиры сцены нужны для движения камеры,
   а очищенное видео остаётся во входе `video` для определения позы.
   Для атак с вращением используйте `root_motion=stationary`:
   режим `in-place` предназначен для движения, которым поворачивает игра,
   и удаляет разворот тела из клипа.
3. **Четвероногое из видео:** сетка → SkinTokens или UniRig → вход `rig`
   MoCapAnything; видео → вход `video`. Это не обещает автоматического
   распознавания анатомии любой птицы, насекомого или произвольного предмета.
4. **Проверить старый риг отдельно:** `animation_tools / prepare-rig`.
   Результат пригоден для последующей анимации; саму анимацию эта операция
   снимает, оставляя собственную позу покоя рига.

Цепочки сохраняются в [studio flow](../../flow/README.md). Для стражника
реально проверены полный граф MIA + Kimodo + перенос, обработка уже
существующих ассетов и прямой граф «видео + риг MIA → GVHMR».
Подготовка также проверена на FBX SkinTokens и UniRig.
Регрессии Blender отдельно проверяют A/T-позы, вращение кисти, поворот курса,
перемещение на месте, веса и сохранение числа кадров.

Контакт рук с оружием, точность нейросетевых суставов и скольжение стоп —
отдельные свойства результата. Исправность рига и переноса не гарантирует
эти контакты: в текущих входах нет геометрии/точек хвата оружия. В новых
цепочках не требуется внешняя правка для совместимости файлов; оценка
художественного качества и игровая интеграция остаются отдельными шагами.

Практический контроль на игровом клипе:
[отладка sword combo](sword-combo-debugging.md).

Для GVHMR применяется отдельный профиль `smpl`: нейтральные таз,
позвоночник, шея и голова сохраняют bind-позу MIA, а движения и повороты
переносятся полностью. Положение суставов SMPL не используется как
команда согнуть корпус рига. Подробнее: [нейтральная поза GVHMR](gvhmr-rest-pose.md).
