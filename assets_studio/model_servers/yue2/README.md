# YuE2 model server

Песни с вокалом по тексту и стилю («Текст → песня», `text-to-song`) по
контракту v1 на основе [YuE2-3B](https://huggingface.co/m-a-p/YuE2-3B)
и официального пакета [yue2-infer](https://github.com/multimodal-art-projection/YuE).

```sh
just setup    # окружение Python 3.12 + PyTorch 2.10/CUDA 12.8 + yue2-infer
just doctor   # PyTorch, GPU, bf16, скачаны ли веса
just serve    # http://127.0.0.1:9110; первый запуск качает ~7,8 ГБ
just test     # объявления, разделение модели на половины, без GPU и весов
```

Веса — CC BY-NC 4.0 с дополнительным разрешением: личное использование и
авторы контента, в том числе монетизация сгенерированной музыки.

## Как пользоваться

- Описание — это **текст песни** с разметкой разделов: `[Verse]`,
  `[Chorus]`, `[Bridge]`.
- «Стиль» — язык, жанр, инструменты, голос, темп, по-английски:
  `Russian, fantasy folk ballad, warm male voice, acoustic guitar, 76 BPM`.
- «План»: `full` — модель сначала пишет мелодию и аккорды (по умолчанию),
  `melody` — только мелодию, `off` — без плана.
- Результат — WAV 48 кГц, стерео. В метаданных — партитура плана в нотации
  ABC (`score`) и признак `truncated`, если модель упёрлась в лимит
  токенов.
- Слишком длинный текст отклоняется сразу: текст, стиль и бюджеты
  партитуры (4096 токенов) и песни (9000) должны поместиться в контекст
  модели (24 576).

## Как это помещается в 8 ГБ

Авторы рассчитывают на 24 ГБ; вся модель — ~7,1 ГБ в bf16. Каждый слой
содержит две копии внимания и MLP: авторегрессионную (AR — партитура и
семантические токены) и потоковую (NAR — акустические латенты). Половины
работают по очереди:

- AR-токены: на GPU — AR-копии слоёв, эмбеддинги и выходная голова,
  NAR-копии в ОЗУ;
- латенты: перед решением каждого куска AR-половина уходит в ОЗУ, а
  NAR-половина приходит на GPU (вместо `yue2.nar._offload_ar`); после
  куска — наоборот, следующему куску нужен AR-префикс;
- VAE: модель целиком уходит в ОЗУ, VAE декодирует кусками по 512 кадров.

Те же веса и те же вычисления, что у авторов; меняется только, где лежат
веса.

- Каждая половина помнит тензоры ОЗУ, в которые загружена, и возвращается
  в них без копирования: с `module.to("cpu")` каждая смена копировала
  половину в новую память, и сервер за две песни вырос до 17,5 ГБ ОЗУ.

| | |
| --- | --- |
| Песня 62 с (куплет и припев) | ~62 с вместе с первой загрузкой модели |
| Две песни 93 и 110 с | ~184 с |
| Пик видеопамяти | 5,7–6,1 ГБ |
| ОЗУ сервера | ~9 ГБ, не растёт от задания к заданию |

Работает один: рядом с другими тяжёлыми серверами не помещается. Один и
тот же запрос с тем же зерном даёт побитово ту же песню.
