# LLM model server

<!-- markdownlint-disable MD013 -->

Генерация и правка текста (`text-to-text`, ADR-003) моделями в формате GGUF.
Модель работает в сервере llama.cpp — закреплённой сборке с CUDA, которую
этот сервер запускает дочерним процессом на свободном порту и с которой
говорит по её OpenAI-совместимому API. PyTorch не нужен.

```sh
just setup                        # окружение + llama.cpp b11312 (~0,8 ГБ)
just doctor                       # сборка, видит ли она GPU, скачаны ли модели
just serve                        # Gemma 4 12B на 127.0.0.1:9106
just serve --model qwen3.8-27b    # Qwen3.8 27B
just test                         # без GPU и весов
```

Из `model_servers/`: `just gemma` (порт 9106) и `just qwen` (порт 9107) —
в студии обе — в разделе «Текст», модель выбирается там же.

## Модели

| `--model` | Файл | Где лежит | Скорость | Характер |
| --- | --- | --- | --- | --- |
| `gemma-4-12b` (по умолчанию) | Q8_0, 12,7 ГБ | ~6,6 ГБ на GPU, остальное в RAM | ~5 токенов/с | грамотная, ровная |
| `qwen3.8-27b` | UD-Q4_K_M, 16,5 ГБ | ~6,3 ГБ на GPU, остальное в RAM | ~3,5 токена/с | богаче деталями, но в Q4 бывают грамматические ошибки |

llama.cpp сам размещает на GPU столько слоёв, сколько помещается
(`--fit`), остальное читает из RAM — поэтому большие модели работают, только
медленнее. Загрузка ~20 с, если файл уже скачан (первый запуск скачивает
12,7 или 16,5 ГБ). Обе — Apache-2.0.

## Параметры

- **Длина ответа** (токенов) и **вариативность** (temperature) — основные;
- top-k и top-p. Умолчания сэмплирования — из карточки модели: Gemma 4 —
  temperature 1,0, top_k 64, top_p 0,95; Qwen3.8 — 1,0, 20, 0,95; min_p 0;
- **размышлять перед ответом** (по умолчанию выключено: для текстов это
  лишь дольше). Размышления в ответ не попадают; на них к длине ответа
  добавляется 4096 токенов, у Qwen3.8 — с усилием «low» (иначе шаблон
  берёт «xhigh» — тысячи токенов);
- **системная инструкция** — по умолчанию «помогаешь делать игру, отвечай
  по-русски, без вступлений»;
- вход **текст** (необязательный) — то, что нужно править или продолжать:
  тогда описание — задание («сократи», «сделай мрачнее»). Так задача
  становится X-to-X и годится для эволюции.

Каждый вариант — отдельный запрос со своим seed и без кеша промпта (иначе
повторно используемый префикс считается другими ядрами GPU): тот же seed
повторяет ответ. Seed 4294967295 llama.cpp считает «случайным» — он
заменяется на 0.

Текст ответа приводится к каноническому (ADR-003). Текст не в UTF-8 и
задание длиннее контекста (16 384 токена) — ошибка запроса (422).

## Устройство

- `runtime.py` — закреплённая сборка llama.cpp (`b11312`, CUDA 12.8) с
  контрольными суммами GitHub; ставится в `~/.cache/assets-studio/llama.cpp`.
- `runtime.py` ставит сборку под блокировкой во временный каталог и
  переносит целиком: два сервера, запущенные одновременно, не мешают
  друг другу.
- Дочерний `llama-server` получает SIGTERM, если этот сервер умирает (даже
  от `kill -9`), — модель не остаётся висеть в видеопамяти. Не загрузился
  — останавливается сразу. Упал между запросами (например, видеопамять
  заняли) — следующий запрос запускает его заново.
- Размышления модели (`reasoning_content`) отделяются и в текст не попадают.
