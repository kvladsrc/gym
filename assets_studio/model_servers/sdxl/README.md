# SDXL model server

Text-to-image и image-to-image по контракту v1 на основе
[SDXL base 1.0](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0)
(CreativeML Open RAIL++-M) с VAE
[sdxl-vae-fp16-fix](https://huggingface.co/madebyollin/sdxl-vae-fp16-fix) (MIT).

```sh
just setup    # окружение Python 3.11 + PyTorch 2.5.1/CUDA 12.4 + diffusers
just doctor   # PyTorch, GPU, скачаны ли веса
just serve    # http://127.0.0.1:9101; веса (~7 ГБ) скачиваются при первом запуске
just test     # размеры картинок, без GPU и весов
```

Рецепты сами входят в `nix develop .#assets-studio-gpu` корневого flake.
Окружение — `~/.cache/assets-studio/venvs/sdxl`, веса — в стандартном кеше
Hugging Face (`~/.cache/huggingface/hub`), закреплены по ревизиям.

- `text-to-image`: размер из стандартных для SDXL (около мегапикселя),
  шаги, следование описанию, «чего избегать».
- `image-to-image`: вход приводится к своим пропорциям при ~1 Мп (стороны
  кратны 64), сила изменения — сколько от исходной картинки меняется.

Варианты генерируются по одному, каждый со своим генератором на CPU: пакет
из четырёх картинок 1024² не помещается в 8 ГБ, а одиночный запрос с seed
варианта воспроизводит его точно. Модели целиком (текстовые кодировщики →
UNet → VAE) переходят на GPU только на свой этап
(`enable_model_cpu_offload`) и возвращаются на CPU после каждого вызова,
в том числе после ошибки.

## Ограничения

- При силе изменения s реально выполняется `шаги × s` шагов (дробная
  часть отбрасывается). Если выходит ноль, запрос отклоняется с
  подсказкой, сколько шагов нужно.
- Картинка с пропорциями уже 1:4 или 4:1 обрезается по центру до 1:4.
- Прозрачные области (RGBA, LA, палитра с прозрачностью) становятся
  белыми; поворот из EXIF учитывается.
- При «следовании описанию» 1 «чего избегать» не действует (нужно больше 1).
- Описание длиннее 77 токенов CLIP обрезается кодировщиком.
- Описания лучше писать по-английски: CLIP плохо понимает русский.
- 4 варианта 1024² по 30 шагов — около полутора минут.
